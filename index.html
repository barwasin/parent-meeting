3 ระบบรางวัล & เส้นทางสู่ World

รางวัลในการแข่งขัน VEX มีทั้งหมด 13 รางวัล แบ่งง่ายๆ เป็น 2 กลุ่ม — กลุ่มที่ “เน้น Engineering Notebook” (กรรมการตัดสิน) และกลุ่มที่ “เน้นผลในสนาม” (Ranking)

📓 เน้น Engineering Notebook (7)

  • Design Award — กระบวนการออกแบบ
  • Innovate Award — นวัตกรรม
  • Create Award — ความคิดสร้างสรรค์
  • Think Award — ความเชี่ยวชาญการเขียนโปรแกรม
  • Build Award — คุณภาพ/ความประณีตของหุ่น
  • Excellence Award + Amaze Award (ใช้ทั้ง EN และผลแข่ง)

🏆 เน้นผลการแข่งขัน (2)

  • Teamwork Champions — คะแนน Teamwork สูงสุดรอบ Final
  • Robot Skills Champion — Driver + Autonomous Skill รวมสูงสุด (มีโอกาสได้ Spot ไป World ถ้าคะแนนสูงสุดในโลก)

รางวัลอื่นในกลุ่ม Teamwork: 2nd / 3rd / 4th / 5th Place

⭐ Excellence Award — รางวัลสูงสุดแห่งความเป็นเลิศ

รางวัลเดียวที่ต้องผ่าน “ทั้งการตัดสิน และผลในสนาม”:

1) Engineering Notebook + Interview — EN ต้องอยู่อันดับสูงสุดหรือใกล้เคียง สัมภาษณ์ดีเยี่ยม (กรรมการให้น้ำหนักถึง 60%)

2) Teamwork & Robot Skill — ต้องอยู่ใน 40% แรกของ Qualifying, Robot Skills และ Autonomous Coding หากตกเกณฑ์ใดเกณฑ์หนึ่งจะหมดสิทธิ์

* ทีมที่ได้ Excellence จะไม่สามารถรับ Judged Award อื่นได้อีก

Method > Medal — Spot ไป World อาจมีการเปลี่ยนแปลง เพราะข้อมูลเดิมเป็นของ RECF แต่ปัจจุบัน VEX แยกตัวจาก RECF แล้วและยังไม่ประกาศใหม่

4 Engineering Design Process (EDP)

“กระบวนการคิดแบบวิศวกร” — ไม่ใช่แค่ทำหุ่น แต่ใช้แก้ทุกปัญหาในชีวิต: คิดเป็นระบบ · ไม่กลัวล้มเหลว · ปรับตัวได้ (แผน A/B/C/D) · ประหยัดเวลา

STEP 1

ระบุปัญหา

เกมนี้ต้องทำอะไร? เป้าหมายคืออะไร?

STEP 2

ระดมความคิด

คิดหลายวิธี ไม่กลัวความคิดแปลกๆ

STEP 3

เลือกวิธีที่ดีที่สุด

เปรียบเทียบแล้วเลือก 1 วิธี

STEP 4

สร้าง / เขียนโปรแกรม

ลงมือสร้างหุ่นตามแผน

STEP 5

ทดสอบ

ลองใช้ดู วัดผลจริง

STEP 6

ทำซ้ำแบบปรับปรุง

แก้จุดอ่อน แล้ววนซ้ำ (Iterate)

REPEAT · ITERATIVE — “You don't get it right the first time” ความผิดพลาดคือข้อมูลให้พัฒนาต่อ

5 Engineering Notebook & การตัดสิน

EN สำคัญกว่าคะแนนจริงไหม? — จริง เพราะ 7 ใน 9 รางวัลที่ตัดสินโดยกรรมการ เน้นที่ Engineering Notebook กรรมการประเมินจาก 2 หน้าหลัก:

Page 1 — Engineering Design Process

  1. Identify the Problem / Design Goal(s)
  2. Brainstorm Solutions
  3. Select Best Solution
  4. Build and Program the Solution
  5. Original Testing of Solutions
  6. Repeat Design Process (Iteration)

Page 2 — Format and Content (5 ข้อ)

  1. Independent Inquiry — สืบค้นด้วยตนเอง (Student-centered)
  2. Usability & Completeness — ทำงานและสมบูรณ์
  3. Originality & Quality — เป็นต้นฉบับและมีคุณภาพ
  4. Organization / Readability — จัดระเบียบ อ่านง่าย
  5. Record of Team & Project Management

6 บทบาทผู้ปกครอง (Student-Centered)

ทีมที่ไปได้ไกล มักเป็นทีมที่ผู้ปกครอง support เป็นทีม — ดูแลด้าน เวลา (รับ-ส่ง/ซ้อม) · ประสานโรงเรียน (แจ้งลาไปแข่ง) · กำลังใจ (ไม่กดดันผล) · การเดินทาง inter · เคารพว่า EN เป็นของเด็ก · สื่อสารผ่าน LINE กลุ่มทีม

1 · Supporting Actor

ทำ:

  • ฟังลูกเล่าเรื่องการเรียนรู้และปัญหา
  • ถามกระตุ้น “ทำไมเลือกวิธีนี้?” “มีวิธีอื่นไหม?”
  • ให้กำลังใจเมื่อติดปัญหา

ไม่ทำ: เขียน EN แทน · คิด/แก้โค้ดแทน · เปรียบเทียบกับเด็กคนอื่น · ทำให้ทั้งหมดเพราะอยากชนะ

“Error is not failure!”

2 · Documentation Assistant
  • ถ่ายรูปลูกขณะทำงาน (ถ้าได้รับอนุญาต)
  • แนะนำการจัดระเบียบสมุด แต่ให้ลูกเขียนเนื้อหาเอง
  • ย้ำให้ลงวันที่และบันทึกความรู้สึกทุกครั้ง
  • ฟีดแบ็คด้วยคำพูดเชิงบวก
3 · Growth Mindset
  • “เรียนรู้สำคัญกว่าชนะ”
  • “ทุกความผิดพลาดคือบทเรียน”
  • “ความพยายามสำคัญกว่าความสามารถ”
แทนที่จะพูดว่า…ลองเปลี่ยนเป็น…
“เก่งจัง!”“เห็นหนูตั้งใจทำมาก!”
“ทำไมไม่ได้อย่างเพื่อน?”“วิธีนี้ยังไม่ได้ผล ลองวิธีใหม่ดูไหม?”
“ต้องได้รางวัล!”“ไม่ว่าผลจะเป็นยังไง แม่ภูมิใจในตัวหนูแล้ว”

7 Team Commitment & Buffet Mode

การฝึกฝนคือทางออก — ทีมที่ iterate บ่อยคือทีมที่ไปไกล

การเข้าฝึกซ้อม

เข้าซ้อมตรงเวลาตามตาราง ใช้ Buffet Mode ซ้อมเพิ่มได้ทุกเมื่อ — การซ้อมเพิ่มคือ unfair advantage

การสื่อสาร

ทุก update ต้องครบ: ทำอะไร แก้อะไร ผลเป็นยังไง ใคร เมื่อไหร่ — ทีมที่สื่อสารชัด iterate เร็วกว่า 2 เท่า

ความรับผิดชอบ

เป็นเจ้าของงานที่ทีมมอบหมาย ทำให้เสร็จตรงเวลา ส่งต่อเพื่อนได้ (VEX G2 Student-centered)

BUFFET MODE — จุดเด่นของ CodeLab Competition Track
✓ ซ้อมนอกเวลาได้ ไม่จำกัดจำนวนครั้ง ✓ สอนแบบโค้ช 1 คน ต่อเด็ก 1 ทีม ✓ หลักสูตรออกแบบ & ปรับปรุงจากประสบการณ์ทีมที่ไประดับโลก ✓ ใช้อุปกรณ์ที่ศูนย์ (ไม่ต้องซื้อชุดเอง)

8 3 Codes for Everyone & VEX G1–G6

Coach Code

CODE · 01
C1 ปัญหา ≠ เด็ก (ปัญหา = ระบบที่ออกแบบไม่ดีพอ)
C2 ชมต่อหน้า · แก้แบบ 1-on-1
C3 ไม่ว่าร้ายต่อหน้าเด็ก / No hate speech
C4 สอน — ไม่ทำแทน (VEX G2)
C5 Feedback สร้างสรรค์ “I noticed X · I felt Y · Could we try Z?”
C6 Safety ก่อน Performance

Student Code

CODE · 02
S1 Method > Medal
S2 ไม่ว่ากัน ไม่โทษกัน “เราจะแก้ยังไง?”
S3 Yes, and… ต่อยอดไอเดียเพื่อน
S4 EN เป็นของเรา — เราเขียน เราทำ
S5 Failure = Data = Improve
S6 ทุ่มเททีมเดียว (1 season = 1 team, VEX G5)

Parent Code

CODE · 03
P1 เด็กทำ — เราชม (ไม่ออกแบบ/ประกอบ/เขียน EN ให้ลูก, VEX G4)
P2 Process > Result “iterate ครั้งนี้เปลี่ยนอะไร?”
P3 ไม่พูดถึงทีมอื่นในแง่ลบ (รวม LINE/Social)
P4 เคารพ Coach Code · concern → คุย 1-on-1 กับโค้ช
P5 แจ้งล่วงหน้า ไม่หายเงียบ
P6 Trust the Process (season 8 เดือนมี ups+downs)
VEX G1–G6 Rules: G1 เคารพทุกคน · G2 Student-centered (เด็กเป็นเจ้าของงาน) · G3 ใช้สามัญสำนึก · G4 งานต้องสะท้อนฝีมือนักเรียน · G5 เด็ก 1 คน = 1 ทีม/season · G6 ผิดโดยไม่ตั้งใจ ≠ จงใจ
